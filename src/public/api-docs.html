Shiftify Backend API Reference

Express + TypeScript + Prisma + PostgreSQL · Australian NDIS marketplace. Flutter and Web clients call these same endpoints.

Base URL

There is no /api prefix. Routes are mounted directly on the app root.

http://localhost:5000   (development)

Authentication

Bearer access token in the Authorization header, obtained from /auth/login or /auth/register.

Authorization: Bearer <accessToken>

Refresh token is set as an httpOnly cookie (shiftify_refresh) and also returned in the response body as a fallback for cross-site mobile/Flutter clients.

Auth badges

PUBLIC no token needed

AUTH valid Bearer token required

ROLE token + specific active role(s)

ADMIN ADMIN / SUPER_ADMIN tier only

Response envelope

Every successful response is wrapped in { data }. List endpoints using pagination wrap items in { data: { items, total, page, limit } }. Errors always come back as { error }, never as a bare 200.

// success
{ "data": { "...": "..." } }

// paginated
{ "data": { "items": [ /* ... */ ], "total": 42, "page": 1, "limit": 20 } }

// error
{ "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [ /* optional */ ] } }

Notes

  • blockManagedSelfService — a MANAGED sub-account (created by a parent Provider/Coordinator via /linking) is blocked from calling this endpoint on itself; the parent acts on its behalf instead.
  • Request bodies shown are the exact Zod validator shapes (fields marked with a default or omitted "optional" note are required). Types are illustrative example values, not literal defaults.
  • Multipart/form-data endpoints (file uploads) are marked accordingly — the JSON shown for those is the non-file form fields only.
